# Mindboard audit — 2026-07-28

Adversarial codebase audit, advisor cross-examination, and the agreed plan of record.

- **Findings:** 68 raised → **42 confirmed**, 26 refuted (~37 unique after dedupe)
- **Fixed and committed** on `ai/audit-fixes-20260728`: 7 (2 critical)
- **Open:** 31, logged as tasks in the Mindboard project group
- **Advisors:** Claude Fable 5 and GPT-5.6-sol, two rounds each (independent, then cross-examined)

---

## 1. Method

Ten finder agents ran in parallel over separate dimensions — finance math, inventory,
MCP/multi-tenancy, React render perf, hooks/leaks, server perf, timezone, motion, a11y,
error handling. Every finding was then handed to an **independent verifier instructed to
refute it**, defaulting to "refuted" under uncertainty.

The refutations are the load-bearing part. 26 of 68 were killed, including several that a
naive scan would have "fixed" into regressions:

| Killed claim | Why it was wrong |
|---|---|
| Index-as-key in `WeekView` re-runs 7 days of layout | Real, but the proposed fix was a behavioural regression |
| Missing `AbortController` on assistant/course-chat SSE | No route reads `request.signal`; the fix delivers nothing |
| Row-exit `setTimeout`s leak on unmount | Setting state after unmount is a documented no-op in React 18+ |
| `DashboardCalendar` needs a month-keyed remount | Already done at both call sites |
| `seedMindspaceTopics` dereferences null | Unreachable; the claim's supporting premise was factually false |

**Verification cost about as much as discovery and was worth it.** A 38% refutation rate
means the finders were correctly tuned for recall, not that they were sloppy.

## 2. Fixed and shipped (branch `ai/audit-fixes-20260728`)

### CRITICAL — MCP OAuth: one-click account takeover

`app/api/mcp/oauth/authorize/route.ts`, `.../register/route.ts`, `app/lib/mcp/oauth.ts`

`/oauth/register` is unauthenticated Dynamic Client Registration and accepted **any** https
`redirect_uri`. `/oauth/authorize` then issued a full-scope authorization code on a bare
**GET** — no consent screen, no CSRF token.

An attacker registers a client pointing at their own host, then gets any signed-in Mindboard
user to load a URL — a cross-site `<img>`, iframe, or redirect suffices, since it is a GET.
The endpoint sees a valid session, mints a code bound to the **victim's** user id, and 302s it
to the attacker. Exchanging it yields a 1h access token + 30d refresh token with scope `mcp`:
full read/write on tasks, finance, inventory, courses, and the private GitHub vault. The victim
observes only a redirect.

Fixed by:
- GET now only **renders a consent screen** naming the client and its redirect host.
- The code is issued by **POST**, gated on a signed consent ticket bound to the session user
  *and* the exact client / redirect / PKCE challenge. Tampering with any of them fails.
- Registration is **host-allowlisted** (`MCP_OAUTH_ALLOWED_REDIRECT_HOSTS`, defaults
  `claude.ai, chatgpt.com, localhost, 127.0.0.1`), matched by exact host or dot-suffixed
  parent — never substring, so `claude.ai.evil.com` and `evilclaude.ai` both fail.
- The consent page sends `X-Frame-Options: DENY` + `frame-ancestors 'none'`.
- 11 new tests, including the CSRF case (ticket bound to a different user) and look-alike hosts.

### CRITICAL — assistant computed "today" on the UTC process clock

`app/lib/assistant/tools.ts:711`, `app/api/assistant/route.ts:131`

Every evening west of UTC the in-app assistant reported *tomorrow*: open tasks read as overdue,
today's spend read as $0, spend limits checked an empty window — while the dashboard beside it
showed the correct day. The MCP twin already resolved this correctly via `todayKey()`; the
in-app path was the straggler. Notably the same function zone-corrected free-time math three
lines below, so this was a genuine miss rather than a design choice.

## 3. Advisor consultation

Both advisors received the identical brief and answered independently, then were shown each
other's memo and made to resolve their disagreements.

### Where they agreed immediately

- **Do not severity-sort.** The finders scored for a generic product; the labels are
  miscalibrated for a single-user app that is also a public multi-tenant server. Sequence by
  **blast radius × irreversibility**.
- **The timezone findings are one defect class, not eight bugs.** Do not patch call sites.
- **The dominant residual security risk is tenant-isolation regression** — one *future*
  service-client query missing `.eq("user_id", …)`. The MCP layer bypasses RLS, so a single
  miss is a full cross-tenant breach. Static finders hunt instances; this is an invariant.
- **Build a two-tenant black-box probe.** Both proposed this unprompted.
- **Stop before the motion tranche.**

### Where they disagreed, and how it resolved

**(A) Timezone enforcement mechanism → resolved, and it largely dissolved.**
Fable wanted `todayISO`'s signature changed to *require* a timeZone argument so `tsc`
enumerates every call site. Sol wanted a `resolveUserClock()` helper at composition
boundaries plus a lint guard.

Fable then found that `todayKey(supabase, userId)` (`app/lib/mcp/config.ts:56`) **already is**
`resolveUserClock` — shipped 2026-07-10. So the only live question was enforcement, and there
the compiler beats lint. Verified in source: `todayISO(timeZone?: string | null)` — the
optional `?` *is* the entire defect class, silently defaulting to the process clock.

**Sol conceded.** Agreed: make the argument required (`string | null`, explicit `null` meaning
"process clock, deliberately" — correct in client components where that *is* the browser),
bless `todayKey`/`safeTimeZone` as the only boundary resolvers, and add one narrow lint rule
for `.toISOString().slice(0,10)` / `toDateKey(new Date())` in `app/lib|actions|api`. No new
clock object; no ambient state. They had each built half of the same answer.

**(B) Spend-history 2000-row cap → resolved, Fable right.**
Sol initially said defer until production data approaches the cap. Fable defended: without
`ORDER BY`, Postgres row order is **unspecified** — the truncation is arbitrary *today*, at any
volume, whenever the planner changes its mind. Verified: `finance.ts:113-118` is
`.gte(...).limit(2000)` with no `.order()`. The failure is a silently wrong money forecast that
still reports `confident: true`.

**Sol conceded**, and sharpened it: order **descending** so truncation costs historical depth
rather than erasing the present, and apply it to every equivalent capped read — not just this
one. Do not paginate or raise the cap; ordering is what makes the cap safe.

**(C) Bottom-sheet focus/a11y → resolved, Sol right.**
Fable initially said never fix — no AT user. Sol refused: "Lucca doesn't use assistive
technology" is not a sound *permanent* disposition for an app any Google account can sign into.

**Fable conceded on Sol's grounds**, and added the argument that settles it: this is not
AT-only. Verified in source — the scrim is a **full-viewport focusable `<button>`**
(`stream-sheets.tsx:20-25`), so keyboard Tab lands on an invisible full-screen control, and
there is no Escape handler, which Lucca hits himself on desktop. `Sheet` is the shared
primitive, so one edit fixes every sheet permanently.

### Residual disagreement (not papered over)

**Sheet exit animation.** Sol closes it permanently — no motion tranche. Fable keeps it: a modal
that vanishes between frames right after a money-logging submit reads as a crash, which is
*comprehension*, Sol's own criterion for what earns a fix — and step 5 already has `Sheet` open
in the editor, so the `animationend`-driven exit rides the same diff.

**Adjudication: Fable's, narrowly.** The marginal cost is near zero once the file is open for
the focus fix, and "reads as a crash" is a real defect rather than polish. This is the one place
the two advisors did not converge.

## 4. Plan of record

Both advisors signed this ordering.

**1 — Tenant boundary** *(highest value; this is new work, not on the findings list)*
Two-tenant black-box probe against a **deployed preview**: seed users A and B with identifiable
data in every domain, enumerate every MCP read/write tool, call each with A's token but B's
object ids and names, assert no B data returns and no B row changes — **including
propose → confirm**. Exercise OAuth over real HTTP: consent binding, redirect equality, PKCE,
replay, wrong client, cross-site GET. Then put the raw service client behind a `scoped()` facade
that *requires* a userId, lint-ban importing it elsewhere, CI-inventory every call site, retire
the legacy static `MCP_BEARER_TOKEN` → owner mapping, and run Supabase `get_advisors`.

**2 — Timezone defect class, one pass**
Required-arg `todayISO`, let `tsc` enumerate callers, repair all confirmed sites, add the narrow
lint rule, add table-driven tests for Vancouver / Tokyo / UTC and both DST boundaries.

**3 — Persisted-data integrity**
Stale absolute inventory quantities → server-side deltas; finance dedup-vs-removed-row;
`ORDER BY` on the capped history reads; archived-item duplication; zero-rate overriding the
manual estimate.

**4 — False-success states**
`/learn` `useState` mirror (currently causes double-paid TTS); discarded inventory mutation
errors; tasks-client optimistic revert; TTS `try/catch` stranding episodes in `rendering`.

**5 — Primary mobile surface**
16px inputs under `pointer: coarse`; 44px destructive targets; then the `Sheet` primitive
(aria-modal, non-tabbable scrim, initial focus, Escape, focus restore) — plus its exit
animation, per the adjudication above.

**6 — Stop.** No motion-polish tranche. Full gates + adversarial review per PR.

### Alternative paths considered

- **One overnight Opus-implementer sprint** against the already-written diffs, reviewed in
  aggregate. Faster; loses per-tier bisectability across 34 changes touching finance math.
  Fable would accept it *only* with tests green per commit.
- **Ship the timezone lint rule now and defer the signature change** until another instance
  appears. Sol's fallback. Weaker: `new Date()` has legitimate uses, so the rule rots.
- **Severity-sorted ticket burndown.** Explicitly rejected by both.

### Consciously closed — do not fix

Worker heartbeat for non-owner tenants (no second tenant exists); cream/sand danger contrast
(dark theme in use — revisit if a tenant picks cream); course-chat client-supplied roles (a
user manipulating their own chat is not a security boundary); index-as-key split rows (loses a
typed draft in a rare flow, no persisted damage); swipe snap-back, stepper digit, and account
panel entrance animations.

## 5. Process notes for the next audit

- **Keep the fan-out and keep the adversarial verifier.** Do not tighten the finders — high
  recall plus a refuting verifier is the right shape, and 38% refuted is healthy.
- **Fix the weak stage: dedupe and unitization.** The "unique" set still contained the OAuth
  critical twice, `recompute.ts:52` twice, and `finance/page.tsx:98` twice, and eight findings
  shared one root cause. Report **root cause + site list**, not per-site findings.
- **Add a calibration pass** that rescores against deployment reality — Vancouver, iPhone PWA,
  dark theme, one real tenant. Severity from a generic finder is not product priority. Example:
  `recompute.ts:52` was filed twice as HIGH but only affects *positive*-offset users; Vancouver
  rows are never dropped.
- **Add an invariant-checker dimension** that hunts *classes* of missing guards — every
  service-client query, every write path — rather than instances.
- **Make the next audit boundary-based** (tenant isolation, OAuth lifecycle, proposal execution,
  vault writes, money derivation) instead of ten generic dimensions.
- Separate **discovery** (permissive) from **proof** (requires a trace or executable repro) from
  **disposition** (calibrated against the real threat model).
