## 2. New findings (ranked by blast radius × irreversibility)

### 2.1 HIGH — The two most powerful credentials in the DB are plaintext; the least powerful are encrypted

- `vault_settings.github_token` — **plaintext** (`0017_vault_settings.sql:5`,
  written raw at `app/actions/brain.ts:74`, read raw at
  `app/lib/brain/vault.ts:111`). This PAT grants **write access to the entire
  second brain** — the repo AGENTS.md calls "who Lucca is".
- `google_tokens.access_token` / `refresh_token` — **plaintext** (`0002`,
  `app/auth/callback/route.ts:37-38`, `utils/google/calendar.ts:140`). The
  refresh token is durable calendar read/write.
- Meanwhile `user_settings.anthropic_api_key` etc. are AES-256-GCM encrypted
  via `encryptSecret` (`app/lib/assistant/crypto.ts`) — the 0015 pattern the
  Connections redesign standardized on.

The trust model is inverted: a Postgres backup leak or service-key exposure
yields the vault and the calendar, but not the API keys. **Fix:** run
`github_token` and both Google token columns through the same
`encryptSecret`/`decryptSecret` pair. Note the backfill **cannot be plain
SQL** — it needs `ASSISTANT_KEY_SECRET`, so it's a one-shot app-side script (or
lazy re-encrypt-on-read with a format sniff: `v1.` prefix = encrypted). Touch
points are small: `readVaultCredentials`, `brain.ts` connect action, the auth
callback, `getGoogleToken`'s read+refresh-write path.

### 2.2 HIGH — AGENTS.md documents an app that no longer exists (the capture core, of all places)

Verified stale, all load-bearing sections:

- **Routes:** `/groups`, `/groups/[id]`, `/inbox` are documented as shipped but
  are **permanent redirects** to `/tasks` (`next.config.ts`). Meanwhile
  `/people`, `/people/[id]`, `/brain`, `/brain/graph`, `/brain/note/[...]`,
  `/mindspace`, `/mindspace/import`, `/plan`, `/tasks`, `/tasks/history`,
  `/week`, `/settings`, `/finance/setup` all exist and are absent from the
  Product State list (People/Learn get their own sections, but the route list
  is the map agents navigate by).
- **Deleted files still cited as key files:** `app/groups/groups-client.tsx`,
  `app/_components/today-client.tsx`, `app/_components/get-started-screen.tsx`,
  and — the one that stings — `app/_components/task-capture-bar.tsx`, which the
  doc calls "the highest-priority interaction". Capture lives in the Dock now;
  the entire "Task UX" section describes a dead component.
- `app/lib/agent/registry.ts` is described as "the architectural spine / the
  seam" — see §3.1; it is imported by nothing.

Concrete failure mode: this file is the context every agent in the fleet boots
from. An agent sent to tweak the capture bar will grep for a file that doesn't
exist, then either flounder or *recreate* it. For an operation that runs
overnight autonomous sessions against this repo, doc rot in AGENTS.md is not a
docs nit — it's corrupted instructions. **Fix:** one rewrite pass over Product
State, Task UX (→ Dock), Design System (get-started reference), and Important
Files. Cheap, high leverage, and worth adding to the definition-of-done for
route-level changes ("if you add/move/delete a route or a file AGENTS.md names,
update AGENTS.md in the same PR" — the whats-new/tours rule already exists;
this is its sibling).

### 2.3 HIGH — No CI

There is no `.github/` directory. Lint and 1302 tests run only when someone (or
some agent) remembers; Vercel's build gates deploys but nothing gates merges.
The whole test suite runs in **under 20 seconds** — a GitHub Actions workflow
(`npm ci && npm run lint && npx tsc --noEmit && npm run test`) plus branch
protection on `main` costs ~30 minutes to set up and permanently upgrades every
overnight `ai/*` branch and every PR. Given the multi-agent workflow, this is
the single highest-leverage process addition available. (Add an
`npm run typecheck` script while at it — today nothing runs `tsc` except full
builds, and the required-argument timezone regime *depends* on the compiler
enumerating call sites.)

### 2.4 MEDIUM — `listCalendarEvents` builds its window on the process clock

`app/lib/mcp/reads.ts:742-744`: `new Date(\`${from}T00:00:00\`)` /
`new Date(\`${to}T00:00:00\`)` parse in the **server's** zone (UTC on Vercel),
so the MCP `list_events` fetch window starts/ends up to 17 hours off the user's
day boundaries — evening events on the last requested day can drop out, and
`from`'s early hours leak in from the prior UTC day. Everything around it does
this correctly (`getScheduleSnapshot` three functions up uses
`zonedWallTimeToUtcMs`; `planning-read.ts:145-148` likewise). This is exactly
the dataflow shape the eslint tripwire documents itself as unable to catch.
Two-line fix + it already has the right neighbors to copy.

### 2.5 MEDIUM — Supabase advisors: 156 RLS initplan warnings, 21 unindexed FKs

- **`auth_rls_initplan` × 156 (WARN):** every RLS policy evaluates
  `auth.uid()` per-row instead of once per statement. One migration rewriting
  policies to `(select auth.uid())` clears all 156. Impact today is small
  (small tables, and the MCP path bypasses RLS anyway), but the app-side
  session client pays it on every page read, and it's a single mechanical
  migration.
- **Unindexed FKs (INFO × 21):** the two that matter are
  `balance_changes.account_id` — `recomputeAccountBalance` filters on it on
  **every finance write** — and `person_interactions.person_id` (dossier log
  reads). The rest can ride along in one migration.
- **Unused indexes (INFO × 5):** `inventory_items_user_group_idx`,
  `spending_categories_user_id_idx`, `ai_audit_log_conversation_idx`,
  `mindspace_topics_user_idx`, `people_user_group_idx`. Verify against query
  patterns before dropping (some may just be young).

### 2.6 MEDIUM — `MCP_BEARER_TOKEN` does double duty

The same static token is (a) the home worker's only credential
(`app/api/worker/route.ts:53`) and (b) a legacy full-access MCP bearer mapped
to the owner (route tail). A compromise of the worker PC — the machine that
also runs yt-dlp against arbitrary Instagram content — yields not just the job
queue but **full owner read/write over MCP**. Minimal fix: introduce
`WORKER_BEARER_TOKEN`, point the worker route at it, and retire the legacy MCP
mapping (the prior audit's still-open recommendation) now that per-user PATs
exist and the owner can mint one in /settings.

### 2.7 LOW — OAuth lifecycle edges (accept or cheap-fix)

- `verifyAccessToken` ignores the embedded `aud` claim (`oauth.ts:223-226`).
  Single-deployment + per-deployment secret makes this near-moot; checking it
  is two lines of defense-in-depth.
- Stateless refresh tokens (30d) and client_ids (1y) have **no revocation**
  short of rotating `MCP_OAUTH_SECRET`, which kills every session. A
  `user_settings.token_generation` int embedded in tokens and checked at
  verify time buys per-user revocation for one column.
- The consent ticket binds user+client+redirect+PKCE but has no single-use
  nonce; within its 5-minute TTL it can mint multiple codes. PKCE makes the
  codes attacker-useless without the verifier, so this is theory, not threat.

### 2.8 LOW — assorted, verified

- `addMinutesToClock` (`writes.ts:1746-1752`) clamps at 23:59 — a time-block or
  event whose duration crosses midnight silently truncates instead of spanning.
- `executePeopleUpdate` error strings are inconsistent: some carry
  `(applied: N)` context, others (`log` insert failure, `checkin`, `set_group`
  DB errors) return the bare message — a partially-applied people batch can be
  harder to reason about than a stock/finance one.
- Two lint warnings: unused `taskA` (test file) and a stale
  `eslint-disable no-control-regex` at `app/lib/mcp/quick-note.ts:113`.
- `proper-lockfile` sits in `dependencies` but is only used by
  `overnight/run.mjs` — harmless, but it belongs in the overnight harness or
  devDependencies.
- Root clutter: `REDESIGN_BRIEF.md`, `REDESIGN_PLAN.md` (2026-07-17),
  `CODEX_HANDOFF.md` (2026-06-01) look finished — candidates for `docs/`.
- Supabase auth: leaked-password protection disabled (WARN). Google-OAuth-only
  makes it ~moot today, but it's a checkbox.

## 3. Opinions

### 3.1 The agent registry is fiction — kill it or crown it

`app/lib/agent/registry.ts` calls itself "the single seam between Mindboard's
data and any AI surface." **Nothing imports it** (one comment in the MCP route
says tool names "mirror" it). The real tool surface lives twice: once in
`app/lib/assistant/tools.ts` (assistant defs + dispatch) and once inline in
`app/api/mcp/[transport]/route.ts` (~1,400 lines of `registerTool` calls), with
names, descriptions, and schemas hand-kept in sync. That's the exact drift the
registry was designed to prevent, with a third divergent copy adding to it.

Either: (a) make the registry authoritative — zod schemas + handler bindings
live there, and both surfaces render from it (the honest version of the
second-brain plan's Phase 2); or (b) delete it and update AGENTS.md +
`docs/second-brain-plan.md` to bless the two-surface reality, with the shared
`proposeXFor`/`EXECUTORS` layer in `writes.ts` acknowledged as the actual seam
(which, to be fair, it has quietly become — and it's a good one). I'd do (b)
now and revisit (a) only if a third surface (the proactive planner) actually
materializes. Speculative abstraction that never got used is better deleted
than half-crowned.

### 3.2 What's genuinely good (brief, but earned)

- **Invariant discipline is exceptional.** `writes.ts`, `sync.ts`, `vault.ts`,
  and `finance-ops.ts` read like the AGENTS.md doctrine was written first and
  the code made to match — comments explain *why* at exactly the places a
  future agent would break things (`{ fresh: false }` justifications, the
  propose-vs-execute date-resolution note, the dedup edge-case ledger).
- The **ordered-cap** fix pattern from the last audit didn't just get applied —
  it got applied *with rationale comments* at new call sites (`writes.ts:598`).
  That's the difference between patching instances and learning the class.
- The worker design (pull-only, no inbound ports, no DB key on the PC, signed
  URLs both directions, atomic SKIP-LOCKED claims, allowlist at both enqueue
  and claim) is textbook.
- 1302 green tests with the pure-logic/fetch-assembly split consistently held.
  The people feature shipped with its §2 doctrine intact in code.

### 3.3 Product opinions (unsolicited, take or leave)

- **The finance fingerprint (`date|direction|cents`) will eventually bite on
  legit duplicates** — two identical coffees on one card, same day, imported
  from a statement: the second is a `skip_duplicate` unless per-op `force` is
  set. The receipt makes it *visible*, which is the right call, but consider
  teaching the import prompt (tool description) to say "if the statement shows
  two identical charges the same day, set force on the second."
- **Observability is thin.** Server errors go to Vercel's ephemeral function
  logs; the MCP `guard()` correctly converts throws to tool errors but nothing
  aggregates them. Before more tenants arrive, a free-tier Sentry (or even a
  Vercel log drain) on the MCP + worker routes would turn "a tenant's sync
  silently stopped" from unknowable into a notification.
- **`user_settings.timezone` still defaults to UTC** and the preferences form
  only *guesses* the real zone without persisting it (AGENTS.md documents this
  as "the normal case, not an edge case"). The documented fix — persist the
  browser's guess on first load when the stored value is still the default —
  removes the whole failure mode for every future tenant. It's a small change
  and it retires a paragraph of doctrine.

## 4. The changes I'd make, in order

1. **CI + branch protection** (§2.3) — lint, `tsc --noEmit`, vitest on every
   PR; add `"typecheck": "tsc --noEmit"` to package.json. ~30 min.
2. **AGENTS.md rewrite pass** (§2.2) — Product State routes, Task UX → Dock,
   Important Files, registry sentence. Plus the "update AGENTS.md in the same
   PR" rule. ~1 hr, mostly deletion.
3. **Encrypt `github_token` + Google tokens** (§2.1) — reuse
   `encryptSecret`; lazy re-encrypt-on-read via `v1.` prefix sniff avoids a
   backfill script entirely. Flagged migration for nothing; it's app-code only.
4. **The two-tenant probe** (prior item 1) — extend `test/isolation-proof.mjs`
   (which the first draft of this report wrongly said didn't exist) beyond the
   tasks domain: A-token attacks on B's ids across every write family, plus a
   deployable smoke mode. This is the artifact that turns "the invariant holds
   today" (verified again, by me, today) into "the invariant is guarded."
5. **`listCalendarEvents` zone fix** (§2.4) — two lines.
6. **One Postgres migration** (§2.5, flagged, not applied): RLS `(select
   auth.uid())` rewrite + FK indexes on `balance_changes.account_id` and
   `person_interactions.person_id` (+ the other 19 while in there).
7. **Split `WORKER_BEARER_TOKEN` from `MCP_BEARER_TOKEN`, retire the legacy
   static MCP mapping** (§2.6) — env change + one route line + worker config.
8. **Delete `app/lib/agent/registry.ts`** and update the two docs (§3.1).
9. Sweep the small stuff (§2.8): two lint warnings, people-executor error
   strings, midnight clamp, root doc moves, leaked-password checkbox.

Items 1–3 are a single afternoon and remove the three standing risks with the
worst blast-radius-to-effort ratios. Item 4 is the one piece of real
engineering; it was the consensus #1 five weeks ago and nothing has shipped it.
